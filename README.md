# REST API Event Project

## Назначение проекта

Учебный проект на **ASP.NET Core Web API**, реализующий базовый
REST‑сервис для управления мероприятиями (Events).\
Сервис предоставляет стандартные CRUD‑операции:

-   создание события
-   получение списка событий
-   получение события по id
-   обновление события
-   удаление события
-   бронирование события

На текущем этапе данные хранятся **в памяти приложения** (in‑memory).
Архитектура разделена на контроллеры, сервисы, DTO и мапперы, что
позволяет в дальнейшем легко заменить хранилище на базу данных.

# API


## Функционал создания мероприятий

### GET /events

Получение списка событий с фильтрацией и пагинацией.

#### Query параметры:
- `title` (string, опционально) — поиск по названию (частичное совпадение, без учёта регистра)
- `from` (DateTime, опционально) — события с датой начала >= указанной
- `to` (DateTime, опционально) — события с датой окончания <= указанной
- `page` (int, по умолчанию 1) — номер страницы
- `pageSize` (int, по умолчанию 10) — количество элементов на странице

#### Ответ:
```json
{
  "totalCount": 10,
  "page": 1,
  "currentItemCount": 5,
  "items": [ ... ]
}
```

### GET /events/{id}

Получение события по id.

Ответ:
- 200 OK — событие найдено
- 404 Not Found — событие не найдено

### POST /events
Тело запроса:
```json
{
  "title": "string",
  "description": "string",
  "startAt": "2026-04-10T10:00:00",
  "endAt": "2026-04-10T12:00:00"
}
```

### DELETE /events/{id}

Удаление события.

Ответ:
- 200 OK — удалено
- 404 Not Found — не найдено

### PUT /events/{id}

Обновление события.

Ответ:
- 200 OK — обновлено
- 404 Not Found — не найдено
- 400 Bad Request — некорректные данные

## Функционал бронирования

### POST /events/{id}/book
Создание брони для события

Ответ:
- 202 Accepted
- В теле: BookingInfoDto
- Заголовок Location: /bookings/{bookingId}

Ошибки:
- 404 — событие не найдено

---

### GET /bookings/{id}
Получение брони по id

Ответ:
- 200 OK — BookingInfoDto
- 404 — бронь не найдена

Booking ответ содержит:
- Id (long) — уникальный идентификатор брони
- EventId (int) — идентификатор события
- Status (BookingStatus) — текущий статус
- CreatedAt (DateTime) — дата создания
- ProcessedAt (DateTime?) — дата обработки (nullable)

### BookingStatus
- Pending — бронь создана, ожидает обработки
- Confirmed — бронь подтверждена
- Rejected — бронь отклонена

---

## Background

Фоновый сервис:
- периодически проверяет брони со статусом Pending
- выполняет задержку (имитация внешнего сервиса)
- переводит бронь в Confirmed
- заполняет ProcessedAt

---

## Пример использования

1. Создать событие:
POST /events

2. Создать бронь:
POST /events/1/book

→ получить 202 + Location

3. Сразу проверить:
GET /bookings/1
→ статус Pending

4. Подождать несколько секунд

5. Проверить снова:
GET /bookings/1
→ статус Confirmed

## Ошибки
Все ошибки-исключения возвращаются в формате ProblemDetails
```json
{
     Status = statusCode,
     Title = title,
     Detail = exception.Message,
     Instance = context.Request.Path
};
```
